# T-006: Zmena hesla odhlási ostatné sessions a zruší reset link (H07)

Vykonávateľ: codex
Stav: hotova
Závisí od: –

## Cieľ
Po úspešnej zmene hesla (`change_password`) musia byť zneplatnené všetky ostatné sessions používateľa a existujúci password-reset token. Aktuálna session (z ktorej používateľ heslo menil) ostáva platná.

## Kontext
- `backend/auth/service.py`: `change_password(user_id, current_password, new_password)` okolo riadku 127 dnes iba robí `UPDATE users SET password_hash, updated_at`.
- Vzor: `confirm_password_reset` (okolo riadku 190–250) v jednej transakcii nuluje `password_reset_token_hash` a `password_reset_expires_at`, revokuje sessions cez `UPDATE auth_sessions SET revoked_at = ? WHERE user_id = ? AND revoked_at IS NULL` a volá `queue_auth_email(conn, user_id, "password_changed")`.
- Route: `change_password_logged_in` v `backend/routers/auth_router.py` okolo riadku 283; session token z cookie sa číta cez `request.cookies.get(cfg.cookie_name)` (okolo riadku 116). Sessions sú v tabuľke `auth_sessions` – pozri, ako sa token mapuje na riadok (hash tokenu) v `service.py`.
- Implementácia: do `change_password` pridaj voliteľný parameter `keep_session_token: str | None = None`. V tej istej transakcii nastav `password_reset_token_hash = NULL, password_reset_expires_at = NULL` a revokuj všetky aktívne sessions používateľa okrem tej, ktorej hash zodpovedá `keep_session_token`. Ak `password_changed` e-mail v `change_password` ešte nie je, doplň `queue_auth_email(conn, user_id, "password_changed")` rovnako ako pri resete. Route odovzdá token z cookie.
